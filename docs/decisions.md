## D-01. Chrome 확장, GitHub Release 배포

- 결정: Manifest V3 확장을 만들고, `x-mesh/notforme`의 GitHub Release로 zip과 릴레이 파일을 배포한다. 웹스토어 등록은 하지 않는다.
- 근거: 사용자 발언 "제품 공개는 릴리즈 된 형태와 github을 통해서 공개함". Chrome 웹스토어는 확장의 전체 로직이 제출한 코드 안에 있어야 하고 개인정보 처리방침·데이터 전송 공개가 필요하다. GitHub 배포에서는 이 부담이 없다.
- 사용자 발언 중 "제품 공개"는 이 확장의 배포를 뜻한다. 같은 말이 D-03에서는 "제품 공개 기사"로 따로 쓰인다.

## D-02. 마케팅 목적의 기사는 전부 숨김

- 결정: 이벤트, 할인, 개점, 협업 한정판, 행사 방문객 수 자랑 등 마케팅 목적의 기사는 모두 광고성 PR로 보고 숨긴다.
- 근거: 에이전트가 경계를 어떻게 잡을지 물었고(기술 사실이 든 제품 공개는 남기고 마케팅 목적만 광고로 보는 안을 권장), 사용자가 "니가 말한 이벤트 등의 마케팅 목적의 기사는 다 없애는 걸로"라고 답했다.

## D-03. 제품 공개 기사는 별도 옵션

- 결정: 제품·서비스·모델·기능 공개를 알리는 기사는 광고성 PR과 분리한다. 체크박스 `제품 기사 없애기`로 켜고 끈다. 기본은 꺼짐.
- 근거: 사용자 발언 "'제품 공개'는 옵션으로 제공한다. '광고기사 없애기' '제품기사 없애기' 등의 체크박스?" 처음 목적이 "제품 공개나 기술을 보고 싶다"였으므로 기본값은 보이는 쪽이다.
- 우선순위: 한 기사가 마케팅 목적이면 광고성 PR이 우선한다(협업 한정판 "출시" 같은 기사).

## D-04. 표시 방식

- 결정: 한 줄 접기와 완전 숨기기를 모두 제공하고 기본은 접기.
- 근거: 사용자 요구 "기사는 가리거나 또는 열을 없애고 보여준다". 에이전트는 오분류를 바로 확인하고 되돌릴 수 있다는 이유로 접기를 기본으로 권했고 사용자가 이의를 달지 않았다. NotForMe의 "읽을 권리" 원칙과도 맞는다.

## D-05. API 키는 로컬 릴레이에만 둠

- 결정: 확장은 키를 저장하지 않는다. `127.0.0.1`의 릴레이가 환경 변수에서 키를 읽는다. 릴레이는 `chrome-extension://` origin만 받는다.
- 근거: Jev 브리지 스킬이 키를 페이지 JavaScript로 보내지 말라고 정한다. 확장에 키를 넣으면 확장 저장소에 평문으로 놓이고, 웹 페이지 origin을 허용하면 아무 사이트나 사용자의 API 크레딧을 쓸 수 있다.
- 비용: 사용자가 릴레이를 직접 실행해야 한다(`prd-v0.1.md` 9절, 13절 5번).

## D-06. 관심 주제 필터

- 결정: 사용자가 관심 주제를 쉼표로 입력하면, 그 주제가 아닌 기사를 숨기는 옵션을 제공한다.
- 근거: 사용자 요구 "사용자가 원하는 토픽이 아닐 때는 없앤다". D-07의 규칙 기반 구조가 구현되면 이 옵션은 규칙의 한 형태로 흡수된다.

## D-07. 규칙 기반 필터로 일반화

- 결정: 고정 체크박스를 규칙 목록으로 바꾼다. 광고성 PR과 제품 공개는 기본 체크박스로 앞에 두고, 정치·혐오·AI·연예·사건사고 등은 규칙 추가로 넣는다. 사용자가 일반 문장으로 규칙을 쓸 수 있다.
- 경위: 사용자가 "뉴스, AI, 혐오, 정치 이런 걸 숨기는 컨셉은 어때?"라고 제안했다. 에이전트가 검색해 보니 이 컨셉은 이미 있었고(`research.md`), 세 가지 방향을 제시했다. (1) 광고성 PR·제품 공개로 좁게 유지, (2) 완전한 규칙 기반 필터로 일반화(Cloak과 정면으로 겹침), (3) 광고성 PR·제품 공개를 기본 제공으로 앞세우고 일반 규칙을 뒤에 두는 혼합. 에이전트가 (3)을 권했고 사용자가 "그래 해보자"라고 답했다.
- 버린 대안: (1)은 개인용 가치가 작아서, (2)는 차별점이 사라져서 택하지 않았다.

## D-08. 이름과 저장소

- 결정: 제품 이름 `NotForMe`, 저장소 `github.com/x-mesh/notforme`, 로컬 경로 `~/work/project/agentic/notforme`.
- 근거: 사용자 발언 "나는 읽을 권리가 있어. 난 보기 싫은 걸 안 볼 권리가 있어. 나를 괴롭히지 마. 이런 뉘앙스의 이름을 생각해봐". "내가 읽을 것은 내가 고른다"는 관점이 `NotForMe`에 담긴다.
- 검토하고 버린 이름은 `research.md` 3절에 있다.

## D-09. 새 개념이라고 주장하지 않음

- 결정: 일반 주제 필터는 이미 있으므로 새로운 개념이라고 소개하지 않는다. 차별점은 한국어 뉴스 사이트, 광고성 PR과 제품 공개의 분리, 접기 중심 표시, 로컬 릴레이 구조로 한정한다.
- 시험(남아 있음): Cloak이나 Smart Filter에서 "광고성 보도자료" 규칙을 직접 써서 지디넷의 같은 24건에 돌려 본다. 비슷하게 걸러지면 광고성 PR 규칙은 차별점이 되지 못한다. 에이전트는 확장을 설치해 시험할 수 없어서 사용자가 직접 해야 한다.

## D-10. 정치·혐오 규칙의 기본 정의

- 결정:
  - 정치: 정당·선거·정치인 중심 기사만. IT·과학 정책 기사는 제외.
  - 혐오·분노 유발: 자극적이고 분노·혐오를 부추기는 기사. 사실 위주의 사건 보도는 제외.
- 근거: 지디넷에는 `국감2026` 탭이 따로 있어서 정치 규칙이 IT 정책 기사까지 숨길 수 있다. 혐오 범죄를 보도하는 기사와 혐오를 부추기는 기사는 다르다. 에이전트가 이 기본값을 제안하며 확인을 구했고 사용자가 "그래 해보자"로 수락했다.
