## 1. 한 줄 정의

뉴스 목록에서 **내가 보기 싫은 기사**(광고성 PR, 제품 공개, 정치, 혐오·분노 유발 등)를 내 기준으로 접거나 숨긴다. 숨긴 기사는 한 번 클릭하면 다시 읽을 수 있다.

## 2. 배경

지디넷코리아 같은 IT 매체의 목록에는 기술 기사 사이에 보도자료 성격의 기사가 많이 섞여 있다. 할인 행사, 신규 출점, 협업 한정판, 행사 방문객 수 자랑 같은 기사다. 사용자는 제품 공개나 기술 기사를 읽고 싶어 한다. 목록을 훑어 가며 직접 걸러 내는 일이 반복된다.

처음 요구는 "현재 페이지에서 Jev로 광고성 PR 기사만 없앨 수 있는가"였다. 같은 날 검증에서 가능하다는 것을 확인했고, 요구가 "광고, 정치, 혐오 같은 보기 싫은 것을 규칙으로 숨기는 도구"로 넓어졌다.

## 3. 원칙

사용자가 정한 이름의 뉘앙스가 곧 제품 원칙이다. 2026-10-29 발언: "나는 읽을 권리가 있어. 난 보기 싫은 걸 안 볼 권리가 있어. 나를 괴롭히지 마."

| 원칙 | 구현 방침 |
| --- | --- |
| 읽을 권리 | 기본은 삭제가 아니라 한 줄 접기다. 클릭하면 원문 목록 항목이 그대로 펼쳐진다. 완전히 숨기기는 사용자가 고르는 옵션이다. |
| 안 볼 권리 | 기준은 사용자가 정한다. 제품이 정치나 주제를 대신 판단해 강제하지 않는다. |
| 괴롭히지 않기 | 확신이 없으면 숨기지 않는다(확률 기준값 이상일 때만). 판정 실패, 서버 오류, 애매한 항목은 모두 보이는 쪽으로 처리한다. |
| 최소 수집 | 기사 본문을 읽거나 보내지 않는다. 항목별 제목과 요약 앞 200자만 판정에 쓴다. |
| 과장하지 않기 | 새로운 개념이라고 주장하지 않는다. 같은 영역에 이미 있는 제품은 `research.md`에 정리했다. |

## 5. 현재 구현 (v0.1 프로토타입)

### 5.1 사용자 기능

팝업 체크박스로 필터를 켜고 끈다.

| 옵션 | 숨기는 기사 | 기본값 |
| --- | --- | --- |
| 광고성 PR 기사 없애기 | 마케팅 목적의 기사 전부. 할인·행사, 신규 출점·팝업, 협업·한정판, 앰배서더, 행사 방문객 수·기념일 홍보, 브랜드가 제공한 통계, 협찬·회사 작성 홍보 | 켜짐 |
| 제품 공개 기사 없애기 | 기업이 제품·서비스·모델·기능을 공개하거나 출시했다는 내용이 중심인 기사(마케팅 목적이면 광고성 PR이 우선) | 꺼짐 |
| 관심 주제가 아닌 기사 없애기 | 사용자가 쉼표로 입력한 관심 주제와 관련 없는 기사 | 꺼짐 |

- 표시 방식: 한 줄 접기(기본), 완전 숨기기.
- 판정 기준값: 0.5~0.99, 기본 0.8.
- 매체가 직접 붙인 `[광고]`, `[PR]`, `[협찬]`, `[보도자료]`, `[스폰서]`, `Sponsored` 접두어는 모델 호출 없이 광고성 PR로 처리한다.
- 같은 기사가 한 페이지에 여러 번 나와도 한 번만 판정한다. 무한 스크롤로 추가되는 항목은 `MutationObserver`로 처리한다.

### 5.2 구조

```
페이지 -> content script -> background worker -> 로컬 릴레이 -> Jev API
          제목+요약 추출      캐시                127.0.0.1:8787   (API 키는 릴레이만 보유)
```

- `extension/src/adapters.js`: 사이트 어댑터. 항목 선택자 `.newsPost`, 제목은 `h2/h3/h4`, 요약은 `.assetText p`(없으면 항목 텍스트에서 제목과 byline을 뺀 앞부분). 기사 ID는 URL의 `no=` 값.
- `extension/src/content.js`: 항목 수집, 로컬 규칙, 분류 요청, 접기·숨기기 적용, 설정 변경 시 재적용. 같은 항목을 같은 설정에서 두 번 요청하지 않도록 `tried` 집합을 둔다(오류 시 DOM 변경마다 요청이 반복되는 문제를 막기 위해).
- `extension/src/background.js`: 릴레이 호출과 `chrome.storage.local` 캐시(최대 3,000건, 오래된 항목부터 제거). 캐시 키는 `정의 버전#주제 키#기사 ID`.
- `relay/server.mjs`: `127.0.0.1`에서만 수신한다. `Origin`이 `chrome-extension://<32자>`가 아니면 403으로 거부한다(웹 페이지가 사용자의 API 크레딧을 쓰지 못하게 하기 위함). `NF_EXTENSION_ID`로 특정 확장만 허용할 수 있다. 요청당 항목 100개, 본문 256 KB, 주제 10개까지. Jev 요청은 30항목씩 나누고 429/529/타임아웃은 최대 2회 재시도한다.
- 환경 변수: `TYPESAFE_API_KEY`(또는 `JEV_API_KEY`), `TYPESAFE_BASE_URL`, `JEV_ENDPOINT`, `TYPESAFE_DEFAULT_MODEL`/`JEV_MODEL`, `NF_PORT`, `NF_EXTENSION_ID`.

### 5.3 분류 방식 (v0.1)

항목마다 Jev `choice` 질문을 둘 던진다.

- `kind`: `ad_pr` / `product_launch` / `news` / `needs_review`. 상호 배타적이며 마케팅 목적이면 `ad_pr`를 우선한다.
- `topic`(주제를 입력한 경우만): `on_topic` / `off_topic` / `needs_review`.

숨김 조건은 해당 라벨의 확률이 기준값 이상일 때다. 라벨 정의 문구는 `relay/server.mjs`의 `KIND_CRITERIA`, `topicCriteria()`에 있고, 정의를 바꾸면 `background.js`의 `DEFINITION_VERSION`을 올려 캐시를 버려야 한다.

## 6. 검증 결과 (2026-10-29)

모두 개발 환경에서의 시험이다. 실제 Chrome에 확장을 설치해서 확인한 것은 아직 없다.

| 항목 | 방법 | 결과 |
| --- | --- | --- |
| 최초 개념 검증 | 지디넷 검색 `무신사`(462건) 첫 페이지 24건을 제목+요약 200자로 Jev에 일괄 질문(0.5초 안에 응답) | `ad_pr` 확률 0.8 이상 10건 숨김. 경계선에서 남긴 것: 시대포럼 기사 0.75, 무신사 뷰티 선출시 기사 0.74, 제네시스 GV90 기술 기사 0.56 |
| 확장 로직 | 같은 `content.js`를 `chrome` API 대역과 함께 검색 페이지에서 실행 | 광고성 PR 8건 접힘(정의를 확장용으로 다시 쓰면서 니케 4주년, 이구홈 성수2호점, 이스트팩 기사가 경계 아래로 내려감). 제품 기사 체크 시 추가 요청 없음 |
| 주제 필터 | 주제 `AI, 반도체, 서버 인프라, 보안` | 9건 추가로 가림 |
| 제품 공개 분류 | 샘플 4건 | GPU 공개·모델 출시·맥북 공개는 `product_launch` 0.97~1.0, 삼성 메모리 수급 전망은 `news` 0.99 |
| 표시 | 스크린샷, 높이 측정 | 접힌 줄 37px. 사이트가 `.newsPost`에 높이 122px와 하단 여백 34px를 고정해 둬서 `content.css`에서 접힌 상태일 때 풀었다 |
| `background.js` | 대역 `chrome` API와 실제 릴레이로 Node 테스트(`test/background.test.mjs`) | 캐시 적중, 주제별 캐시 분리, 릴레이 불가 시 오류 반환 통과 |
| 릴레이 보안 | `curl` | 웹 페이지 origin 403, 확장 origin 200, 잘못된 본문 400 |

**알려진 한계와 미확인 사항**

- 분류 정확도를 라벨링된 데이터로 측정하지 않았다. 숨긴 10건은 사람이 제목을 읽고 광고성 PR로 보인다고 확인했을 뿐이다.
- 시험 장치의 문제: 페이지에서 `127.0.0.1`로 직접 `fetch`하면 브라우저의 로컬 네트워크 접근 제한에 걸려 응답이 오지 않았다. 실제 확장은 서비스 워커에서 호출하므로 해당하지 않는 것으로 보이나(추정), 실제 설치 후 확인이 필요하다.
- 목록 사이드바(`지금 뜨는 기사` 등)의 `.newsPost`도 같은 규칙으로 처리된다. 지디넷의 다른 목록 레이아웃(기자·시리즈 페이지 등)은 확인하지 않았다.

## 7. 다음 구조: 규칙 기반 필터 (미구현, 결정 D-07)

고정 체크박스 3개를 **규칙 목록**으로 바꾼다.

### 7.1 사용자에게 보이는 것

- 기본 제공 체크박스(앞쪽): `광고성 PR`(기본 켜짐), `제품 공개`(기본 꺼짐).
- 규칙 추가(뒤쪽): 기본 제공 규칙 `정치`, `혐오·분노 유발`, `AI`, `연예`, `사건사고`와 사용자가 일반 문장으로 쓰는 규칙.
- 규칙마다 켜기/끄기, 편집, 삭제. 기본 제공 규칙의 정의 문구도 보고 고칠 수 있어야 한다.
- 접힌 줄에는 걸린 규칙의 이름을 보여 준다.

### 7.2 기본 제공 규칙의 기본 정의 (사용자 확인됨)

| 규칙 | 기본 정의 |
| --- | --- |
| 정치 | 정당·선거·정치인 중심 기사. **IT·과학 정책 기사(예: 국감의 IT 이슈)는 제외**한다. 지디넷에 `국감2026` 탭이 따로 있어 정치 규칙이 IT 정책 기사까지 숨기지 않게 하려는 것이다. |
| 혐오·분노 유발 | 자극적이고 분노·혐오를 부추기는 기사. 혐오 범죄를 사실 위주로 보도하는 기사는 제외한다. |
| 광고성 PR | 5.1절의 정의 그대로. |
| 제품 공개 | 5.1절의 정의 그대로. 마케팅 목적이면 광고성 PR이 우선한다. |
| AI, 연예, 사건사고 | 아직 정의 문구를 쓰지 않았다. 구현 시 정한다. |

### 7.3 판정 방식(안)

- 규칙마다 항목별 yes/no 질문을 하나씩 던진다(Jev `noul`). 상호 배타적인 `choice` 대신 다중 라벨로 바꾸는 것이다. 한 기사가 여러 규칙에 동시에 걸릴 수 있다.
- 숨김 조건: 켜진 규칙 중 하나라도 P(yes)가 기준값 이상이면 숨긴다.
- 캐시 키: `정의 버전 # 규칙 ID # 정의 해시 # 기사 ID`. 규칙 하나를 바꿔도 다른 규칙의 캐시는 살린다.
- 질문 수가 `항목 수 × 규칙 수`로 늘어난다(30항목·5규칙이면 요청당 150질문). 요청 크기에 대한 Jev의 상한은 확인하지 못했으므로 구현 전에 확인해서 분할 기준을 정한다.
- 규칙별 기준값을 둘지는 미정이다(13절).

## 8. 법적 고려

법률 자문이 아니다. 근거와 출처는 `research.md`에 있다.

- 개인 브라우저에서 화면 표시만 바꾸는 방식은 광고 차단 확장 프로그램과 같은 종류다. 독일 연방대법원은 2018년에 광고 차단이 불법이 아니라고 판결했다.
- 같은 사건의 저작권 쟁점(DOM 같은 브라우저 내부 구조를 프로그램의 변형으로 볼 수 있는가)은 2025-07-31 연방대법원이 하급심 판단을 파기하고 환송했고 아직 확정되지 않았다. 한국 판례는 찾지 못했다.
- 위험이 커지는 경우: 기사 본문·목록을 서버로 모아 재배포, 유료·로그인 우회, 대량 수집. 이 제품은 이 세 가지를 하지 않는다.
- Jev로 보내는 정보는 제목과 요약 200자다. 어떤 기사 목록을 열어 봤는지가 Jev에 전달되므로 README에 밝혀야 한다(현재 README는 전송 항목만 적고 있다).

## 9. 포지셔닝

- 일반 주제 필터는 이미 있다(Cloak, Smart Filter, PeaceFeed 등). 새로운 개념이라고 소개하지 않는다.
- 차별점 후보: 한국어 뉴스 사이트, 광고성 PR과 제품 공개를 분리한 기본 규칙, 접기 중심의 되돌릴 수 있는 표시, 로컬 릴레이로 API 키를 확장 밖에 두는 구조.
- 불리한 점: 릴레이를 직접 실행해야 하는 설치 부담. 설정 없이 쓰는 제품보다 불리하다.
- 차별점이 실제로 있는지 가르는 시험(결정 D-09): Cloak이나 Smart Filter에서 "광고성 보도자료" 규칙을 직접 써서 지디넷의 같은 24건에 돌려 보고 비슷하게 걸러지는지 본다. 비슷하면 이 제품의 광고성 PR 규칙은 차별점이 되지 못한다.

## 10. 배포

- 저장소: `github.com/x-mesh/notforme` (결정됨). 로컬 작업 사본은 `~/work/project/agentic/notforme`이고 `origin`만 설정했다. 첫 커밋과 push는 하지 않았다.
- 산출물: `scripts/package.sh`가 `dist/notforme-extension-<version>.zip`과 `dist/notforme-relay-<version>.mjs`를 만든다. GitHub Release에 두 파일을 올린다.
- 설치: zip을 풀어 `chrome://extensions`에서 압축해제된 확장으로 로드하고, 릴레이를 `node notforme-relay-<version>.mjs`로 실행한다. Node.js 18 이상.
- 문서는 영문 `README.md`와 한국어 `README.ko.md`를 함께 둔다.
- 라이선스는 정하지 않았다.

## 11. 이름

## 13. 미결 사항

1. 규칙별 기준값을 둘지, 전역 기준값 하나로 갈지.
2. Jev 모델 버전을 고정할지. 릴레이의 기본 모델은 `jev-latest`다. `dorkitude/skimmer`는 평가에 쓴 `jev-1.14.0`을 고정해서 별칭이 바뀌어도 답이 달라지지 않게 한다. 이 확장도 정의 버전과 모델 버전을 함께 캐시 키에 넣는 방안을 검토한다.
3. 요청 크기 상한(7.3절)과 분할 기준.
4. 다른 한국 뉴스 사이트 어댑터의 범위(GeekNews, 네이버 등).
5. 릴레이 설치 부담을 줄일 방법. 확장에 사용자의 API 키를 직접 넣는 방식은 쉽지만 키가 확장 저장소에 놓이는 보안 비용이 있다.
6. 정확도 평가 방법. 지디넷 목록 수백 건에 사람이 라벨을 붙인 평가 세트를 만들지.
7. 라이선스.
8. `AI`, `연예`, `사건사고` 규칙의 기본 정의.
9. 지디넷의 다른 목록 레이아웃 확인.
